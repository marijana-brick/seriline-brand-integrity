# Seriline-specific review gates

Run these gates before delivery, adjusting to the actual medium.

1. **Product truth:** Are Serix IAM, Serix Online, Visitor, Cidron, Serix ID, and related products named and scoped correctly? Is every technical feature supported by current documentation?
2. **Trust:** Are security, privacy, GDPR, accreditation, integration and turnaround claims evidenced and appropriately caveated? Never infer guarantees.
3. **Visual identity:** Did the creator reuse approved Seriline logos/templates/assets? If missing, is the design explicitly provisional rather than represented as approved?
4. **Distinctiveness:** Would this look like a generic identity-security vendor if the logo were removed? Replace abstract padlocks, neon circuit backgrounds, AI-generated glass objects and decorative gradient cards with authentic devices, process illustrations, or real Seriline context.
5. **Copy:** Does every headline/CTA address an actual job or product? Remove 'unlock / revolutionize / seamless / cutting-edge' boilerplate without replacing it with clumsy over-specificity.
6. **Operational clarity:** Does the artifact distinguish roles, identities, credentials, permissions, hardware and visitor workflows accurately? In UI, validate dangerous/irreversible access changes with appropriate confirmation and least-privilege clarity.
7. **Locale:** Is English or Swedish consistent and technically accurate, with product names preserved?
8. **Format QA:** Did the output render correctly in its target tool and pass readability/accessibility tests? Be explicit when not checked.

On handoff, state: brand sources used, approved vs provisional choices, and blocking review needs. Keep the handoff short.
